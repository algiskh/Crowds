# T-001 — Синглтоны-сервисы → DI (ecslite-di)

**Статус:** в работе
**Создана:** 2026-11-25

## Цель

Убрать из мира ECS «синглтон-сущности», которые на деле являются сервисами или конфигами (holder'ы, пулы,
менеджеры, UI-вью), и внедрять их в системы через [ecslite-di](https://github.com/Leopotam/ecslite-di)
(`EcsCustomInject<T>`, плюс `EcsWorldInject` / `EcsPoolInject<T>` / `EcsFilterInject<Inc<…>>` вместо
`GetPool`/`Filter` в `Run`). Зависимости системы должны быть видны в её полях.

**Не цель:** игровое состояние (`WeaponComponent`, `AmmoInventoryComponent`, `ReloadingComponent`,
`FragCountComponent`, `DifficultyComponent`, `GrenadeStateComponent`…), запросы/события (`Request*`, `*Event*`)
и `PlayerComponent` остаются в мире — это нормальное использование ECS. Контейнер (VContainer) — вне этой
задачи, см. «Решения».

## Как устроено

- Пакет `com.leopotam.ecslite.di` (`Packages/manifest.json`, тег `2025.4.22` — та же версия, что и ecslite).
- `EntryPoint.RegisterSystems()`: после всех `.Add(...)` — `.Inject(<сервисы>)`, затем `.Init()`.
  Custom inject подбирается по типу, первый подходящий экземпляр. Передавать узкие сервисы/конфиги, **не
  `MainHolder`** (иначе он снова станет god-object'ом). `null` в списке допустим — поле останется `null`.
- Сервисы создаются в `EntryPoint.SetupSpawnData()` (до `PoolPrewarmer.RunAsync` и `RegisterSystems`) и
  хранятся в полях `EntryPoint`.
- **Мост на время миграции:** синглтон-компонент остаётся, но держит тот же экземпляр сервиса
  (`EffectPoolComponent { EffectPool Value; }`). Непереведённые системы работают как раньше; компонент
  удаляется, когда его больше никто не читает.
- Статические хелперы (`GrenadeLauncher`, `DyingMobSystem.ReturnToPool`, `PoolPrewarmer`) инъекцию не получают —
  сервис им передаётся параметром из вызывающей системы / `EntryPoint`.
- Шаблон новой системы:

```csharp
using Leopotam.EcsLite;
using Leopotam.EcsLite.Di;

public class FooSystem : IEcsRunSystem
{
	private readonly EcsWorldInject _world = default;
	private readonly EcsFilterInject<Inc<FooComponent>> _foos = default;
	private readonly EcsCustomInject<SoundHolder> _sounds = default;

	public void Run(IEcsSystems systems)
	{
		foreach (var e in _foos.Value)
		{
			ref var foo = ref _foos.Pools.Inc1.Get(e);
			// _sounds.Value...
		}
	}
}
```

## Решения

1. 2026-11-25 — DI для систем через ecslite-di, без контейнера. VContainer (не Zenject: заброшен, медленнее,
   больше магии) рассмотреть позже, только для уровня приложения: меню, межсценовые сервисы
   (`LevelProgress`/`ILevelStatsStore`, `IControlSettingsStore`, лидерборд, `LoadingScreen`) и MonoBehaviour
   на сцене (`SmartConditions/*Wrapper`, UI).
2. 2026-11-25 — Миграция по одной системе с мостом совместимости; синглтон-компонент удаляется последним.

## Что проверить

После каждого шага — Play mode, без ошибок в консоли:
- **Эффекты (шаг 1, 3):** смерть мобов (эффект смерти), попадания, DoT-эффекты на мобах (яд/токсик держится, пока
  жив модификатор, и не «воскресает» на переиспользованном мобе), бонусы скорости/щита (эффект следует за
  игроком), след гранаты и взрыв. Прогрев пулов на загрузке — без всплывающих эффектов в кадре.
- **Перезарядка (шаг 1):** магазинная (звук начала + затвор), поштучная у дробовика (прерывание выстрелом),
  R при полном магазине / без патронов — ничего не происходит.
- **Урон (шаг 1):** неуязвимость после удара (толпа бьёт один раз), щит режет урон, смерть игрока → fail.
- Уровни: Tutorial, Key, Infinite Scroll (`Level_01`, переиспользование секторов), Hockey.
